Build a production-quality immersive web experience called:

"MONSOON WINDOW"

Tagline:
"Somewhere between the rain and the radio."

The website should feel like the user is sitting inside an Indian apartment during monsoon season, looking through a large window at the city outside while listening to a carefully curated stream of music.

This is NOT a conventional music player.

It should feel like an atmospheric digital place that the user can leave open for hours.

IMPORTANT:
- Create an original visual identity.
- Do not copy any existing website's source code, branding, layout, artwork, or exact visual design.
- The experience should be inspired by Indian monsoon nostalgia, rainy evenings, old apartments, FM radio, chai, city traffic, and music.
- Prioritize atmosphere, animation, sound, typography, and small details.
- The website should feel cinematic but intimate.
- Avoid generic "rainy wallpaper" aesthetics.

TECH STACK

Use:
- Next.js
- React
- TypeScript
- Tailwind CSS
- CSS animations
- Canvas/WebGL only where useful
- HTML5 audio / legally permitted external music playback
- Componentized architecture

Make the site responsive and optimized for desktop and mobile.

==================================================

The entire website should represent a single room.

The user is sitting inside near a large window.

Outside the window is an Indian city during monsoon season.

Inside the room:

- old wooden desk
- warm table lamp
- steaming cup of chai
- small FM radio
- notebook/book
- curtains moving slightly from the wind
- occasional condensation on the window
- subtle reflections on the glass

Outside:

- traffic
- motorcycles
- buses
- apartment buildings
- balconies
- streetlights
- trees moving in the wind
- umbrellas
- distant headlights
- occasional lightning
- puddles reflecting lights

The room should remain recognizable throughout the entire day.

==================================================
BACKGROUND SCENE SYSTEM
==================================================

DO NOT hardcode one background image.

Create a modular background system.

Each time period should support its own visual scene.

Example:

/public/scenes/

dawn/
morning/
heavy-rain/
golden-hour/
evening/
night/
deep-night/

Each scene can contain:

- background image
- optional looping video
- optional animated GIF
- foreground rain layer
- lighting overlay
- particles
- environmental effects

Create a reusable SceneManager component.

The SceneManager should:

1. Determine local time.
2. Determine the current scene.
3. Load the appropriate assets.
4. Crossfade between scenes.
5. Never create a harsh visual cut.
6. Continue running if the user leaves the page open.
7. Update automatically as time changes.

When transitioning between scenes:

- fade current scene out
- fade next scene in
- gradually modify lighting
- gradually modify rain intensity
- gradually modify ambient audio
- gradually modify traffic density

The transition should feel like time is naturally passing.

==================================================
BACKGROUND MEDIA
==================================================

The implementation must support three types of background:

1. STATIC IMAGE
2. LOOPING VIDEO
3. ANIMATED PROCEDURAL BACKGROUND

Do not assume every scene needs video.

Use the most efficient medium for each scene.

For example:

Dawn:
static image + procedural rain

Heavy rain:
looping video + rain overlay

Night:
looping video + animated headlights

Deep night:
static image + procedural rain + particles

The architecture should allow these assets to be swapped without changing application logic.

==================================================
TRANSITION SYSTEM
==================================================

This is critical.

Do NOT switch scenes abruptly.

Example:

At 18:25:

- daylight gradually becomes warmer
- sky becomes darker
- street lights slowly appear
- traffic headlights become more visible
- interior lamp becomes brighter
- rain changes intensity
- music program transitions
- ambient sound changes

By 18:30 the evening scene is fully active.

Use long, cinematic transitions.

==================================================
MOBILE
==================================================

Mobile should feel like looking through a phone-sized window.

Do not simply shrink desktop.

On mobile:

- prioritize window
- radio/player remains accessible
- secondary objects can disappear
- maintain atmospheric background
- controls should be thumb friendly

==================================================
PERFORMANCE
==================================================

This is extremely important.

- Optimize all video assets.
- Use WebM/MP4 where appropriate.
- Lazy-load scenes that are not currently needed.
- Do not load every day's worth of video simultaneously.
- Pause inactive video elements.
- Use requestAnimationFrame efficiently.
- Reduce particle counts on mobile.
- Respect prefers-reduced-motion.
- Pause expensive animations when the tab is hidden.
- Avoid unnecessary React re-renders.

==================================================
MOST IMPORTANT CREATIVE REQUIREMENT
==================================================

The website should not feel like:

"Here is a rainy background + music player."

It should feel like:

"You are sitting in a real apartment during monsoon season, and time is passing outside the window."

The user should be able to open the site at 8 AM and leave it open until midnight.

At 8 AM it should feel like morning.

At 1 PM it should feel like afternoon.

At 5 PM it should feel like golden-hour rain.

At 8 PM it should feel like a rainy city night.

At 2 AM it should feel almost completely silent.

The website should tell the passage of time without requiring the user to look at a clock.

FINAL REQUIREMENT

Before finishing:

- Test every time period.
- Test scene transitions.
- Test mobile.
- Test desktop.
- Test background video fallback.
- Test image fallback.
- Test reduced motion.
- Test audio autoplay restrictions.
- Test leaving the page open for several hours.
- Ensure no memory leaks from Canvas/video/audio.
- Ensure inactive scenes are unloaded or paused.
- Ensure the experience remains smooth on mid-range mobile devices.

The final result should feel like a beautiful interactive monsoon memory rather than a website.
